# Copy in the interface

Words are design material. The direction's **copy voice** sets headline and marketing tone; UI microcopy stays plain in every voice.

- Write from the user's side, in their words: "Manage notifications", not "Webhook config".
- Buttons: [Verb] [object] — "Save changes", "Book appointment", "Download receipt". Never "OK", "Submit", "Click here", "Learn more" without an object.
- An action keeps its name through the flow: "Publish" → toast "Published".
- Errors: "[What failed]. [Likely cause]. [How to fix]." — "Payment didn't go through. Your card was declined. Try another card or contact your bank." Errors don't apologise, don't blame, and never lose the user's input.
- Inline validation: "[Field] [requirement]" — "Password needs at least 8 characters."
- Empty states: what this space is for + one action. "No readings saved yet. Save one from today's reading to find it here."
- Confirmations of destructive actions name the thing and the consequence: "Delete 'Q3 report'? This can't be undone." Buttons: "Delete report" / "Cancel".
- Sentence case for everything (titles, buttons, labels). Short: aim for ~7th-grade reading level; one idea per sentence.
- Specific beats clever. Real content beats placeholder: write believable product copy, real-looking names (match the audience's region — e.g. Saudi/Pakistani names for local apps), plausible numbers (1,284 not 10,000+).
- Banned filler: unlock, elevate, seamless, supercharge, revolutionise, cutting-edge, empower, "Welcome to X", three-adjective taglines.
- Respect product-specific wording rules recorded in memory (for example claims about pricing or "free").
